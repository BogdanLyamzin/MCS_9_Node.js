# Polling chat demo

Невеликий чат для демонстрації **short polling**. Дані зберігаються лише в пам'яті Node.js-процесу: перезапуск сервера очищує чат.

## Запуск

Потрібен Node.js 20+.

```bash
npm install
npm run dev
```

Відкрийте `http://localhost:3000` у двох вікнах браузера. В одному виберіть Марину, у другому — Андрія. Відправте повідомлення й зверніть увагу на індикатор наступної перевірки та записи в консолі сервера.

## Що відбувається

1. Надсилання — `POST /messages`: сервер додає повідомлення до масиву та одразу повертає `201 Created` лише авторові запиту.
2. Кожна вкладка раз на 2 секунди надсилає `GET /messages?after=<id>`.
3. Якщо в масиві є повідомлення з більшим `id`, сервер віддає їх у відповіді. Якщо ні — все одно повертає `200` і порожній масив.

Тобто сервер не ініціює повідомлення для Андрія: саме браузер Андрія постійно запитує, чи з'явилось щось нове. Для наочності сервер логує кожен polling-запит, зокрема й ті, що не знайшли нових повідомлень.

## Корисні точки для пояснення

- Змініть `POLLING_INTERVAL_MS` у `client/app/page.tsx` на `500`: оновлення стане швидшим, але в консолі сервера буде значно більше порожніх запитів.
- Відкрийте 5–10 вкладок: кожна створює свій незалежний таймер та потік `GET`-запитів.
- Тимчасово вимкніть сервер: у UI з'явиться помилка. Polling не тримає постійного каналу — клієнт просто пробує знову під час наступного інтервалу.

Для наступного уроку цей контракт легко замінити на WebSocket: замість `setInterval + GET /messages` сервер зможе сам надсилати подію всім підключеним клієнтам.
