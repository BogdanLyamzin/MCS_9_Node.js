# Long polling: чат без бази даних

Демонстраційний застосунок, який порівнює періодичне опитування з тривалим опитуванням (long polling). Повідомлення та відкриті HTTP-відповіді існують лише в пам'яті Node.js-процесу.

## Запуск

Потрібен Node.js 20+.

```bash
npm install
npm run dev
```

Відкрийте `http://localhost:3000` у двох вкладках. У вкладках оберіть різних учасників, надішліть повідомлення і подивіться на консоль сервера.

## Що демонструє приклад

### Періодичне опитування

За polling браузер створює таймер і раз на `N` секунд виконує `GET /messages?after=<id>`. Сервер відповідає негайно: нові повідомлення або порожній масив. Менший інтервал знижує затримку, але створює багато запитів, які найчастіше не несуть корисних даних.

```ts
setInterval(async () => {
  const { data } = await axios.get("/messages", { params: { after: lastMessageId } });
  renderMessages(data.messages);
}, 3000);
```

Якщо 10 000 вкладок опитують сервер раз на секунду, це 10 000 HTTP-запитів щосекунди — включно з заголовками, cookie, перевіркою авторизації і можливим зверненням до БД — навіть якщо 99% відповідей порожні.

### Тривале опитування

У цьому проєкті клієнт не має таймера. Він відправляє `GET /subscribe?after=<id>`, а сервер залишає відповідь відкритою. Після створення повідомлення сервер негайно відповідає всім вкладкам, які чекали. Клієнт обробляє дані й одразу створює наступний довгий запит.

```ts
async function subscribe() {
  const { data } = await axios.get("/subscribe", { params: { after: lastMessageId } });
  renderMessages(data.messages);
  subscribe();
}

subscribe();
```

У консолі бекенда видно життєвий цикл: `[LONG POLL OPEN]`, `[LONG POLL RESOLVE]`, `[LONG POLL TIMEOUT]`. У будь-який момент кожна вкладка має один очікуючий запит. Таймаут у 25 секунд потрібен, щоб мережеві проксі не закривали дуже довге з'єднання: після нього клієнт відразу підписується знову.

Long polling прибирає постійні порожні запити та майже прибирає затримку, але не скасовує HTTP-витрат. Для кожного повідомлення відповідь закривається, а клієнт відкриває новий HTTP-запит із заголовками й авторизацією. WebSocket розв'язує саме цю проблему, створюючи один постійний двосторонній канал.
